# Account types and hosted tunnels

Decision for #1172, based on `origin/dev` at `4d6c962efab9a3a4c3c9598a52875efd62d5c0ad`, 24 November 2026. An approved bridge of an account with tunnel access gets its own Cloudflare Tunnel and public HTTPS origin. The SPA and Electron use Build's existing authenticated REST, SSE and terminal WSS protocols. A saved personal HTTPS address has priority. Accounts without the entitlement retain WebRTC and Add by URL. Account type and tunnel access can change independently.

This is a design for review. The [security checklist](<Account Types and Hosted Tunnels Security Checklist.md>) defines the evidence required for activation. New paths stay dormant during rollout until the enforcement, clients and operator controls below are present.

## Account and device authority

Build owns account policy in skriftapp. Add `BuildAccountPolicy` to `skriftapp/buildapp/models.py`, keyed by a unique, cascading foreign key to Skrift's `users.id`. Store `account_type` (text constrained to `free|admin`, server default `free`), `tunnel_access` (non-null boolean, default false) and a monotonic policy revision. Keep the requested transition and per-device drain acknowledgements separately from the effective boolean so an interrupted promotion can resume or be cancelled. Put reads and the single transactional update in `skriftapp/buildapp/accounts.py`. Use a Build Alembic revision after the current Build head `a910b2c3d4e5` in `skriftapp/migrations/versions/`. Backfill free/false for existing users. A missing row reads as free/false, including signups made by older workers and users restored from an older database. Create the row on first policy write under the user lock. Test migration with real existing users, approvals and HTTP grants. Schema rollback is safe only after access has been removed, connector cleanup confirmed and all new workers drained.

An admin is a Build account classification. Existing Skrift role checks, invite/alpha membership, suspension, passkey login and desktop OAuth continue to govern their current surfaces. Neither classification grants permission to another account's bridge or to Skrift admin pages. All four type/entitlement combinations are valid. Only the entitlement selects managed transport. Pairing approval in `skriftapp/buildapp/devices_controller.py` binds a device to its owner. Pending registrations, public status reads and device-supplied owner fields cannot allocate tunnels.

Provide an operator-only `python -m buildapp.account_policy` with `show` and idempotent `set --user-id <UUID> --type admin --tunnel-access on`. Support independent field changes and explicit `off`. Require the target environment and verify the issuer/database identity before mutation. The command displays the verified target and proposed revision on dry-run, requires the observed revision on apply and records actor, time, target, old/new values and affected device count. No credentials in output. Implement the dev entry point as `scripts/buildctl --env dev account set …` in `tools/buildctl/buildctl/cli.py` using the database guard pattern in `skriftapp/buildapp/dev_bootstrap.py`. Production uses the module in an authorized production operator job. There is no browser mutation or username heuristic. Do not infer Zech's identity from the first user, display name or an email baked into a migration.

Serialize approval, entitlement mutation, unpairing, account deletion and membership suspension against the same owner/device policy fence. In that transaction update desired state for **all** approved bridges, including offline ones, and enqueue reconciliation. Keep the three-approved-device account limit. An account-type-only update queues no transport change. Lock affected devices in stable order and make approval recheck owner, slot limit and latest effective policy. Re-pairing an ID with different identity/owner creates a new ownership generation.

## Provisioning and cleanup

**Ownership.** Add a desired-state ledger and outbox in skriftapp (proposed `buildapp/hosted_tunnels.py` and its migration). One current row per device ownership generation, one unique tunnel name and hostname. Allocate a disabled (catch-all 404) route for an offline bridge so that it can receive its reserved tunnel and DNS identity on first start. Record environment, owner/device IDs, identity binding, policy revision, desired presence, provider tunnel/DNS IDs, connector credential generation, configuration version, readiness and bounded retry reason. Keep cleanup tombstones with these IDs after parent rows disappear. A new generation never inherits old names, tokens or grants. Pending, failed and unsupported devices remain visible to the owner without an address being suggested as ready.

**Worker.** Run a separate skriftapp reconciliation process with the same database and a leased work queue. Cloudflare calls run outside approval and database locks. A per-device lease, generation check on every result and periodic inventory sweep recover crashes, duplicate deliveries, missed events and manual deletion. Use a random 128-bit opaque label persisted *before* the first call, e.g. `b-<base32-id>.<environment-bridge-zone>`. Use one label below an operator-owned zone with certificate coverage. Use a dedicated registrable domain separate from the sign-in origin and separate dev/prod zones and credentials. Neither the DNS name nor the deterministic provider name derived from that label contains an email, username or device name. The user-supplied address is only a client setting. It never supplies Cloudflare ingress configuration.

Zech supplies it through the deployment secret manager as a mounted Kubernetes Secret for the provisioning process only. Keep it out of Git, app/relay/bridge environments, migration jobs, browser bundles and the TURN credential flow in `ice_servers.py`. The issuer can request a single assigned tunnel token over an authenticated private worker interface. The worker checks current device and ownership generation again before using `GET …/cfd_tunnel/{id}/token`. Only transient memory holds the upstream token at hosted. Treat create, read and rotation responses as secrets. Use timeouts, no redirects, TLS verification and redacted error categories. [Cloudflare setup API](https://developers.cloudflare.com/tunnel/get-started/) · [Origin parameters](https://developers.cloudflare.com/tunnel/reference/origin-parameters/)

**Bridge delivery.** Add a device-only poll/claim route beside `skriftapp/buildapp/bridge_http_controller.py`, reached directly at the originally paired issuer over verified HTTPS. Extend `bridge_http_proofs.py` and `bridge/src/http/discovery.rs` with distinct proof purposes and audiences for policy, connector claim and acknowledgement. Use the registered Ed25519 key, a one-use short-lived server nonce, expiry, device ID, generation, capability and payload digest. Record JTI/spend in SQL, lock and recheck current approval, membership, ownership and entitlement. After the worker call, recheck the generation before returning a bounded no-store response. Repeated delivery after response loss needs a fresh signed request for the same generation. The public pairing-status route, relay, user device list, push, WebRTC and project RPCs never carry this token. A connector credential gives its holder the ability to attach a replica and receive tunnel traffic. It cannot authorize a Build client or manage the Cloudflare account.

**Rotation.** Serialise operator rotations by tunnel generation. Suspend publication/claims during cutover. PATCH the tunnel with a fresh random secret of at least 32 bytes, advance the credential generation, force-disconnect existing replicas and reissue only to the approved bridge. If a PATCH outcome is unknown, keep the route fenced and reconcile by completing a fresh rotation before issuing. For suspected compromise, revoke hosted families and advance the endpoint epoch as well. Restore service after the daemon acknowledges the new generation and the provider confirms the replacement connection. A single bridge may briefly disconnect. Rotate the account-level API token independently in the secret manager, validate minimal permissions, then revoke the old token. [Cloudflare rotation and disconnect semantics](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/configure-tunnels/remote-tunnel-permissions/)

## Bridge listener and connector

Require operator-installed `cloudflared` on the **service PATH** for entitled bridges. This lets the platform package manager authenticate and update the binary and keeps the bridge installer free of a second download chain. Require a supported patched package providing `--token-file` (introduced in 2025.4.0). Resolve a trusted absolute executable once from service-owned directories, never from a project, current directory or login-shell hook. Missing/old binary produces a cached setup reason; a free bridge needs no package. [Cloudflare run parameters](https://developers.cloudflare.com/tunnel/reference/run-parameters/)

Extend `bridge/src/http/{settings,tls,endpoint_state,supervisor,listener,runtime}.rs`. Leave manual `BRIDGE_HTTP_*` resolution intact. Give the managed listener its own persisted state, restart marker, descriptor and private runtime directory keyed by issuer/device. Generate a device-local CA and leaf for a reserved local DNS SAN unique to this assignment, protect the CA key and TLS key, put only the CA certificate in the connector trust pool. Verify SNI with `originServerName`, preserve the assigned external authority with `httpHostHeader`, keep certificate verification enabled. Reserve the loopback port while signed configuration and endpoint registration complete. A restarted process verifies or republishes its actual port before starting the connector. A port belongs to only one prepared listener. A replaced socket must still present the expected private-CA certificate. Keep per-listener Openings/identity fences and share daemon-wide work, connection, stream and terminal memory limits so a second listener cannot double them.

`EndpointPolicy` currently fingerprints the **local leaf certificate**, approved issuer/device, canonical public origin and allowed origins. Include the managed assignment generation and endpoint kind in the new hosted record and signed authority. A certificate or authority change advances its endpoint epoch. Preserve the manual state-file format, predecessor CAS, durable acknowledgement before listen, ordinary-stop deactivation and invocation-specific managed restart behavior. The discovery fingerprint used by a client is the **paired device identity key**. The public browser certificate belongs to Cloudflare. Comparing the edge leaf to the bridge's loopback leaf would break both browser trust and edge certificate rotation.

Own one connector child per current assignment on the bridge liveness runtime (`bridge/src/liveness.rs`, new `bridge/src/hosted_tunnel.rs`). Use direct exec, no shell, a minimal environment and a private CWD. Start only after valid policy and listener acknowledgement. Keep the token in a 0600 owner-only file in a 0700 per-invocation runtime directory, atomically created without following symlinks. Pass only its path using `tunnel run --token-file <path>`. Do not use token argv/env or install a second system service. Disable self-update, bind any local metrics socket to loopback, discard raw child output and emit only fixed health/exit categories. Exclude the directory from backups, migrate/copy, diagnostic bundles and agent worktrees. Clean stale files on startup and unlink on stop/rotation. Same-UID code or root on the bridge remains inside the local trust boundary.

Reap on exit, back off with jitter, and keep pairing/heartbeat and local agents alive through connector failure. Cancel by generation on revoke, disable, shutdown, identity change or replacement. Terminate, wait, kill after a bounded grace period and confirm reap before restart. Under systemd/launchd prove an unclean bridge exit cannot leave a serving orphan (service process-group cleanup or a parent-lifetime watchdog). The daemon needs a fresh issuer policy at startup and a 60-second management lease while serving hosted, renewed every 20 seconds. Measure from request start on a monotonic clock, cap at the issuer deadline and reject late replies. On expiry close hosted admissions/streams and the child. Failure to reach the issuer cannot enable RTC. Reconnects open a fresh application session without replaying uncertain mutations or terminal input.

## HTTPS identity and what a hostname reveals

The browser's TLS session ends at Cloudflare. Cloudflare can observe and alter ordinary REST requests, SSE events and terminal frames, including code, prompts, file bodies, diffs, terminal input/output, bearer headers and upgrade tickets. A second encrypted hop to the connector and verified TLS to the listener protect transport on those hops. Cloudflare is a trusted data-plane processor for this option. An independently sealed value keeps only its own cryptographic guarantees. Build's issuer still learns account, bridge, endpoint and grant metadata. A scoped management credential is powerful too: changing remote ingress can redirect the connector to other locally reachable services. Protect and audit provider configuration access accordingly.

1. A signed-in browser session or a desktop OAuth parent passes `build_auth_guard`. The client requests `POST /api/devices/{id}/http-discovery` for the exact owned origin. It posts the challenge to `/.well-known/build-bridge`. The bridge signs a purpose-limited identity proof. At `/api/bridge-discovery/complete`, skriftapp verifies paired Ed25519 identity, owner/active membership, client binding, nonce, issuer, origin, enabled registration and endpoint/authorization epochs before spending the challenge. Hosted also requires the current assignment. A saved valid family can renew via `/api/devices/{id}/http-credentials`.
2. Only the resulting opaque `bhttp_` bearer (hashed at rest, lifetime at most five minutes, capped by desktop parent expiry) authenticates the client at the listener. The bridge signs a token-bound assertion for `/api/bridge-http/introspect`. The verifier matches issuer/account/device/origin/family/epochs/scope and expiry, then mounts an Opening at `POST /v1/sessions`. Protected REST/SSE requests bind bearer and Opening. Local positive authorization lasts at most 30 seconds from verification start and never beyond token expiry. A revoke denies new hosted verification immediately. Live streams close on local invalidation or by that bounded freshness deadline.
3. Terminal WSS requires a current Opening and bearer to POST `/v1/terminal-tickets`, then an exact-Origin upgrade with its one-use, Opening-bound ticket (at most 15 seconds). Preserve subprotocol handling, expiry, fencing and revocation in `bridge/src/http/{policy,terminal_upgrade,runtime/terminal_tickets}.rs`. Neither cookies, a connector token, provider headers, hostname knowledge nor a tunnel connection authenticates the caller.
4. A person with only the name can resolve DNS, connect to Cloudflare, observe reachability/errors, send OPTIONS and request a rate-limited signed discovery proof with well-formed challenge material. The proof can reveal the public device/endpoint identity and epoch. It supplies no owner session, REST/SSE data, terminal or right to mint a grant. Unauthenticated load still costs resources. Keep pre-auth byte/time/concurrency limits and the global discovery limiter. The listener sees a loopback connector peer; never trust forwarded IP headers to bypass limits. Apply edge limits for abuse and bypass cache on all bridge paths. Disable credential/body/subprotocol capture in logs and tracing. Do not forward app cookies or OAuth to a bridge. Preserve redirect refusal, exact Host, Origin, TLS, browser local-network permission and the bounded per-account HTTPS/WSS document CSP.

## Transport policy, cache and compatibility

**Two registrations, one selected address.** Today `BridgeHttpEndpoint.device_id` is unique and `register_endpoint` revokes device-wide families when the origin changes. Retain that table and the original proof shape for the manual slot. Add a separate hosted endpoint keyed by device/ownership generation with its own CAS chain. Add a default-manual endpoint kind to families. Resolve discovery by the signed origin and exact approved device, renewal by the family's stored slot, introspection by the same slot. Bind hosted registration to the assigned origin and current assignment. Reserve managed zones against manual registration and forbid ambiguous origins. Reject a hosted proof on a legacy/manual registration route. Scope policy-change revocation to the affected slot, while device unpair, suspension and owner change still revoke both. Include both valid registrations in `bridge_http_policy.py::document_origins` with the existing cap and saved-device prioritization. Roll all issuer workers forward before accepting hosted writes.

**Bootstrap before hello.** Extend the signed device policy poll to carry bridge capability `hostedTunnel.v1`, terminal WSS support and current generation acknowledgement. Mirror implementation support in `bridge/src/api/mod.rs`, `fixtures/api/versions.json` and the SPA adapter at the next available additive wire minor. A greeting over an already-working connection cannot bootstrap the first connection. Only a verified device assertion can establish bridge support. Only the account API can decide entitlement. Keep the advertised terminal descriptor and the actual native terminal IPC capability as separate checks at open time.

Extend the owned `GET /api/devices` summary with an additive `transport_policy` object containing schema version, revision, RTC permission, managed state (off/preparing/ready/update required/setup required), and the canonical origin and endpoint generation when ready. A closed enum gives displayable reasons for pending setup. Never return connector or client credentials in this projection. `spa/src/api.js::fetchDevices` and `spa/src/devices.js` commit to `DEVICES_ADDRESS` and reread through its existing generation and account-epoch guard. Combine that cached row with the account/device-scoped preference in `spa/src/core/httpConnectionPreferences.js`. Use one pure selector in the connection owner and transport settings. Views render the committed selection, source and setup reason before any connection attempt, including offline and on cold mount. Connection rings and negotiated diagnostics retain their specific meanings. A successful socket, a timeout, presence and relay availability cannot change policy.

An entitled user can paste a managed address into Add by URL. Classify it from the verified issuer registration as hosted, with the same disclosure and WSS-only rule. A fresh successful list retires an absent device. Failed pulls preserve last-good data. Handle cached pre-feature records by fetching fresh membership before auto-dial when policy is missing. Persist the issuer schema marker alongside the account cache and prevent stale responses from downgrading an issuer already seen to support policy. An old issuer with no policy support uses its existing free/manual behavior. A new issuer advertises the schema in its authenticated response even for empty lists. On account switch clear the active projection and in-memory secrets. Fence stale async attempts, cross-tab writes and desktop handles by account/device, policy revision, slot, origin and endpoint epoch. Explicitly close old application/terminal lifetimes when selection or permission changes. Keep the saved personal setting across an entitlement change. Never silently switch a user from a private path to an edge-readable path because of a connection error.

**Enforce beyond the SPA.** `spa/src/connection.js`, `core/httpConnections.js`, `core/httpDeviceConnection.js`, `core/httpSession.js` and `core/terminalPeerLinks.js` select application and terminal independently. Today a missing `terminal_websocket` descriptor *or* missing `endpoint.openTerminal` can choose WebRTC. Pass `rtc_allowed` into both selectors, recovery, manual switch, and terminal mint. An entitled device without WSS can still use working REST/SSE. Show cached terminal compatibility when known. Electron loads the same SPA. Use `desktop/src/bridge-http{,-settings,-network,-terminal,-ipc}.mjs` for main-process discovery, scoped credential custody, certificate verification and WSS. A new SPA paired with an older preload reports the exact feature requiring a desktop upgrade. Keep arbitrary URLs and raw native handles/bearers outside renderer authority.

In `skriftapp/buildapp/rtc_controller.py`, the existing guard accepts signed-in alpha members and the POST has **no device argument**. All approved devices of an account share its entitlement. Deny the legacy and new ICE requests for an entitled or transitioning account before `ice_servers.py` calls Cloudflare, and similarly deny its RTC gateway-token mint. Preserve the old request/response for free accounts. TURN credentials already minted last until provider expiry. STUN, cached ICE and existing relay tokens make ICE denial alone insufficient. Add RTC admission to `devices_controller.py`'s internal device record, `bridge/src/bin/relay.rs` and `bridge/src/relay_server.rs`: check current owner/policy on device authentication and on new session routing, including already-open sockets, and invalidate prior admissions on generation change. Check directly at admission or use a revocation fence with equivalent ordering. Keep relay ownership/signaling semantics for free accounts.

Use `bridge/src/main.rs`, `bridge/src/liveness.rs`, `bridge/src/relay.rs` and the peer/session owners in `bridge/src/{carrier,rtc}.rs` to gate relay and peer creation and **close existing app AND terminal peers**. Keep the signed API heartbeat and update checks independent. An established DataChannel can outlive rendezvous. For an existing free account, stage promotion: persist a pending revision, deny new RTC admissions at the issuer/relay, command every paired bridge to persist the fence and drain peers, and require signed acknowledgements for that revision before committing effective tunnel access. An offline or legacy device blocks the switch until upgraded and drained, or the operator verifies that daemon is stopped and removes its pairing. A lost relay heartbeat alone cannot prove that. Keep the owning device set stable under the same transaction fence. A newly approved device during transition starts fenced. A legacy bridge newly paired to an already entitled account gets no relay admissions and the listing says to update. Old clients may understand Add by URL and use the existing verified HTTPS path. Their RTC attempts are refused even if they ignore new fields. Refresh/update instructions are available from the issuer independently of bridge connectivity.

For entitlement removal, withdraw hosted authority and drain or expire its management lease before publishing RTC eligibility for that device. An old “on” assertion cannot reopen a deleted assignment. A provider outage can delay physical cleanup without restoring hosted access. The kill switch pauses new provisioning and can withdraw hosted routes; an outage never flips the entitlement to free. To undo rollout, use the same explicit revoke/drain path, compare provider inventory to tombstones, then revert clients/servers. Never roll old admission code into a fleet with active entitlements. Update `tools/buildctl/buildctl/bridge.py` deployment verification: for entitled mode verify a fresh signed policy/endpoint/connector acknowledgement for the exact new invocation alongside the existing PID/binary checks. Keep fresh relay authentication as the free-mode witness.
