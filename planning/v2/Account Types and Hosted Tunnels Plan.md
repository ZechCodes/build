For #1172, revised after #1173 against dev `4d6c962efab9a3a4c3c9598a52875efd62d5c0ad`. Promotion takes effect in one account update. A bridge with a configured personal origin serves that address. In `buildapp/models.py`, add a Build-owned row keyed by Skrift `users.id`, with a constrained account type (`free` or `admin`), independent boolean `tunnel_access` and a promotion revision for disclosure. Migrate after `a910b2c3d4e5` in `skriftapp/migrations/versions/`. Existing and new accounts default to free/false, including users with no policy row during rolling upgrades. All four combinations work. Skrift roles, alpha membership, pairing approval and the three-device cap keep their existing meaning.

Provide an idempotent, operator-only `python -m buildapp.account_policy set --env <env> --user-id <UUID> --type admin --tunnel-access on` with dry-run, independent field updates and an audit of actor, target and old/new values. The dev entry point is `scripts/buildctl --env dev account set …` in `tools/buildctl/buildctl/cli.py`, using the environment checks in `skriftapp/buildapp/dev_bootstrap.py`. The command flips the boolean even when a paired machine is offline. There is no client acknowledgement prerequisite.

The dev wrapper takes `--context` or `DEV_CONTEXT` and uses the authenticated Kubernetes principal as the audit actor. It requires operator access to exec in the dev app deployment. Direct invocations default to the effective OS UID as actor. Either field can be set on its own, and `--dry-run` previews the change without writing policy or audit rows. The promotion revision increases each time tunnel access goes from off to on.

**One decision for Zech — RTC before first readiness.** Recommend allowing WebRTC for a bridge awaiting its first hosted address. Store `hosted_ready_once` on the approved device pairing, independently of the replaceable tunnel row. Set it on the first matching enabled endpoint registration, DNS binding and active connector for that assignment. Keep it through restarts, outages, rotation and entitlement changes for the same pairing. A new owner/pairing starts fresh. Compute `rtc_allowed` once at the issuer: free of the entitlement, or the bootstrap exception is enabled and the entitled device is awaiting hosted setup, has no configured personal endpoint and has never been ready. A personal endpoint on an entitled bridge always uses HTTPS. To choose “never”, disable only that exception. Both variants use the same wire fields and client selector. Preserve a known personal registration while waiting for a newer mode report.

| Policy at the issuer | Client behavior for a new connection |
| --- | --- |
| No tunnel entitlement | Existing WebRTC default, or the user's selected HTTPS address with its current terminal compatibility. |
| Entitled, personal origin configured | Use the registered personal HTTPS address. If setup fails, show its reason. No hosted allocation or automatic switch. |

The current `POST /api/rtc/ice-servers` and `/api/gateway-token` have no target device argument. Keep their legacy behavior for non-entitled accounts. For entitled accounts, refuse both unscoped requests. A modern client can request the bootstrap exception with a target device ID. Both handlers load the approved, caller-owned device and check the same predicate **before** minting anything. Deny foreign, missing, personal and previously-ready targets. ICE credentials and gateway tokens retain their existing provider/account scope. Per-device signaling admission comes from the relay's device record. See `skriftapp/buildapp/{rtc_controller,devices_controller,ice_servers}.py` and `spa/src/api.js`.

Add `rtc_allowed` to `GET /internal/devices/{id}`. Read it in initial device authentication and the **existing 60-second recheck** in `bridge/src/bin/relay.rs` and `bridge/src/relay_server.rs`. A negative answer severs the device's signaling socket on the next check. An unreachable issuer refuses a new socket and preserves an already authenticated socket until a definitive answer. A carried, encrypted DataChannel can outlive its signaling socket. Let it end naturally. Neither peer drain nor an offline bridge delays promotion. Pass the target ID through SPA rendezvous and peer creation in both application and terminal call paths. Roll the additive issuer response out before relay enforcement and enable entitlements only after both are deployed.

## Provisioning and lifecycle

**Choose the origin on the bridge.** Consult `BRIDGE_HTTP_ORIGIN` before claiming hosted mode in `bridge/src/http/settings.rs`. When a personal origin is set, honor existing enablement, validation, TLS and registration, including a disabled or misconfigured listener. Report personal mode in the signed request below so a previous hosted assignment can be removed. Personal tunnels, VPNs, Tailscale and self-hosted addresses keep the existing URL workflow. With no personal origin, a capable approved bridge requests hosted setup from its paired issuer. An offline, unreported or legacy bridge waits for that capability report before allocating resources. A mere pairing status lookup cannot trigger provisioning.

**Reconcile desired state.** Add a skriftapp provisioner process and one durable assignment row per eligible bridge. Record owner/pairing identity, generation, random 128-bit label, provider tunnel/DNS IDs and observed state. Commit the row and a per-generation encrypted connector secret before the first provider call. Dev and prod use separate credentials and distinct host prefixes in the shared, tunnel-only `builduser.net` zone. Use `bd-<label>.builduser.net` for dev and `b-<label>.builduser.net` for prod. Scope tunnel names and DNS ownership comments by hostname prefix and zone, and sweep only that namespace. Use the `*.builduser.net` edge certificate. Forbid per-host certificate issuance so certificate-transparency entries do not enumerate bridge names.

1. A periodic loop compares approval, membership, entitlement and reported personal/hosted mode with provider inventory. Nudge it on changes. Use a single elected reconciler per environment, authoritative DB reads and a generation check before and after external I/O. If the database or inventory cannot be read completely, defer creates and orphan removal.
2. Create a locally managed tunnel using `POST /accounts/{account_id}/cfd_tunnel`, the reserved name, `config_src=local` and a random secret of at least 32 bytes. Create a proxied CNAME via `POST /zones/{zone_id}/dns_records` targeting `<tunnel-id>.cfargotunnel.com`. The server creates only these resources. After an uncertain create, adopt by **exact name** in the environment's namespace, checking local management and the expected DNS target. Leave collisions for the operator. Retry 429/5xx with capped backoff and jitter. Either capacity limit produces a cached setup reason. Purchases require operator action. [Cloudflare create API](https://developers.cloudflare.com/api/resources/zero_trust/subresources/tunnels/subresources/cloudflared/methods/create/)
3. Unpairing, loss of entitlement/membership or choosing a personal origin immediately denies new hosted claims, registration and grant verification for the obsolete assignment. Disable the matching hosted endpoint and revoke its families transactionally, preserving a current personal registration. The sweep removes Build-owned CNAMEs without a live matching row, confirms absence, disconnects replicas and deletes the corresponding tunnels. Recheck row and provider IDs before deletion. Serialize create and cleanup for each label. Unknown ownership or a failed DNS deletion holds tunnel deletion. Crashes, missed nudges and late provider writes converge on subsequent sweeps. No outbox or tombstones.
4. **Rotate by deleting and recreating.** Withdraw the old origin and its grants, delete its DNS and tunnel in that order, confirm both deletions on the existing assignment row, then provision a fresh generation with a new label, secret and UUID. Use the normal sweep and claim flow, including after response loss. The old connector cannot join the new tunnel. Keep the pairing's first-ready bit.

Zech provisions the Cloudflare token as an environment-specific Kubernetes Secret mounted only in the provisioner. Grant account-level Tunnel Write and DNS Edit scoped only to `builduser.net`. Keep it separate from TURN, the relay and the bridge. Encrypt the per-tunnel secret with an environment wrapping key outside the database and bind ciphertext to the pairing/generation. The authenticated issuer can release only the current per-tunnel credential. For local JSON credentials, combine the account tag, tunnel UUID and decrypted tunnel secret only after verifying the claim. Use no-store responses, no redirects, bounded sizes and redacted errors. Keep secrets out of logs, argv, process environment, browser/desktop credentials, backups of runtime files and diagnostic bundles.

**Claim with the registered device key.** There is no signed policy poll today. The public device status route is unauthenticated and heartbeat uses an in-process replay guard. Add a device-only challenge/claim beside `skriftapp/buildapp/bridge_http_controller.py`, using `bridge_http_proofs.py::verify`, the registration challenge pattern, SQL `BridgeHttpReplay` and atomic challenge spend in `bridge_http_auth.py`. Use distinct audience/purpose, bounded expiry, nonce/JTI and signed mode/capability. Check the pinned Ed25519 key, active owner and approved pairing. Return off/personal/setup, or the assigned hostname, generation and that tunnel's connector credential to the bridge over verified issuer HTTPS. Recheck the current assignment before release. Invoke on startup, including service restarts that apply local environment changes. A non-secret entitlement revision hint in the normal heartbeat response wakes an already-running bridge on promotion or removal. The hint triggers a signed recheck and conveys no authority. Retry pending setup with backoff and a fresh proof. This route bootstraps the connection before a bridge hello is possible.

**Use the existing registration.** `BridgeHttpEndpoint.device_id` is unique in `bridge_http_models.py`. `bridge_http_auth.py::register_endpoint` revokes device grant families when **origin, endpoint epoch or enabled state** changes. A change between personal and hosted uses that same predecessor CAS, durable acknowledgement and renewal/discovery flow. Validate a Build-hosted origin against the current assignment on registration, discovery, renewal and introspection. An obsolete daemon cannot republish a removed origin. One device has one origin at a time.

### Hosted claim wire contract

Send both requests to the paired issuer over verified HTTPS with redirect following disabled. Each request has `Content-Type: application/json` and a body with one member, `{"proof":"<compact JWS>"}`. The JSON body limit is 18,000 bytes and the proof limit is 16,000 characters. Use the paired Ed25519 key and JOSE header `alg: EdDSA` plus the route's exact `typ`. The issuer checks approval, the pinned pairing key, active account and alpha membership. Browser session and desktop OAuth credentials are unnecessary.

| POST path | JWS `typ` | Additional signed claims | Success |
| --- | --- | --- | --- |
| `/api/devices/{device_id}/hosted-tunnel/challenge` | `build-http-hosted-tunnel-challenge+jwt` | `mode`, `hosted_capable` | 201 with `challenge_id` (UUID), `nonce` (32 random bytes encoded as unpadded base64url), `expires_at` (Unix seconds, 60 seconds after issuance), and `generation` (positive integer for a current ready assignment, otherwise null). |
| `/api/devices/{device_id}/hosted-tunnel` | `build-http-hosted-tunnel-claim+jwt` | Same `mode` and `hosted_capable`, and the exact `challenge_id`, `nonce` and `generation` from the challenge, including a null generation. | 200 with one result below. |

Both proofs carry the canonical device UUID as `iss` and `sub`, the canonical issuer HTTPS origin plus the full request path as `aud`, integer Unix timestamps `iat` and `exp` at most 30 seconds apart, and a fresh random `jti` of 16–128 ASCII letters, digits, underscores or hyphens. The issuer allows five seconds of timestamp skew. Proofs and challenges are single use. A challenge binds its generation and report to the pairing that issued it. After a mode or capability change is accepted, outstanding challenges for the preceding report revision are refused.

A non-null generation fits the exact JSON integer range, 1 through 2⁵³−1. The provisioner starts generations in the 52-bit range, so the bridge should store them in a 64-bit integer.

`mode` is `personal` whenever a local personal origin is configured, including invalid or disabled settings. Use `hosted` to request hosted setup when there is no personal origin, or `off` to withdraw the request. `hosted_capable` is a JSON boolean. The claim commits the signed report. A personal report withdraws any hosted registration and triggers the provisioner to remove the previous assignment and resources.

| 200 result | Meaning |
| --- | --- |
| `{"status":"off"}` | Tunnel access is off for the owner or the bridge reported `off`. |
| `{"status":"personal"}` | An entitled bridge reported a personal origin. Use the existing personal configuration. |
| `{"status":"setup","reason":"<code>"}` | `provisioning`, `capacity`, `collision`, `update_required` (the bridge lacks hosted capability), or `assignment_changed` (a fresh challenge is required). |
| `{"status":"assigned","hostname":"<prefix>-….<zone>","generation":4,"credentials":{…}}` | The current ready assignment. `credentials` is a local cloudflared credentials object with string fields `AccountTag`, `TunnelID` (canonical UUID) and `TunnelSecret` (standard base64). The bridge uses its own local ingress rules. |

Application responses carry `Cache-Control: no-store` and `Referrer-Policy: no-referrer`. Error bodies contain only `error`, with 400 `invalid_request`, 401 `device_proof_refused` (including stale pairing, invalid/expired proof or challenge, and replay), 413 `request_too_large`, 429 `challenge_budget_exhausted`, or 503 `claim_unavailable`. Retry a lost response or a retryable setup result with backoff, a new challenge request and fresh proofs. Start the exchange on boot or a mode change. A changed `entitlement_revision` integer in a successful `POST /api/devices/heartbeat` response also triggers a signed recheck. Compare it for inequality and treat it as a hint only.

For a hosted endpoint, sign `assignment_generation` in the existing endpoint registration proof and use the exact `https://<hostname>` from the assignment. Omit that field for personal registrations. A bridge can register with `enabled: false` before starting the connector and remain eligible for the RTC bootstrap exception. Once the connector and listener are ready, send an enabled registration at a fresh endpoint epoch with the disabled registration as the predecessor. The first matching enabled registration latches `hosted_ready_once` on the pairing. A ready assignment awaiting an enabled registration appears in the transport projection with `origin: null` and `reason: null`.

The issuer uses the assignment row’s canonical hostname and matching label. Both `b-<32 lowercase hex digits>` and `bd-<32 lowercase hex digits>` stay reserved under every domain, regardless of issuer configuration or assignment removal. Worker and issuer require `HOSTED_TUNNEL_HOST_PREFIX` for provisioning and assignment validation. Only the provisioner reads `HOSTED_TUNNEL_ZONE_NAME`. The issuer materializer uses `HOSTED_TUNNEL_ACCOUNT_ID` and the mounted key file named by `HOSTED_TUNNEL_WRAPPING_KEY_FILE`. The provisioner loads `HOSTED_TUNNEL_MODE_SOURCE=buildapp.hosted_tunnel_source:hosted_mode_source` during startup. The bridge allows exactly the two shipped prefixes, `b` and `bd`, to keep its input check narrow without inferring the issuer's environment. The issuer remains authoritative for the exact hostname.

The [signed claim fixtures](fixtures/hosted-tunnel-claim.json) contain both requests and responses for personal, provisioning and assigned results, with a test key and synthetic connector credential. Their timestamps are fixed for offline verification.

## Bridge package and ingress

On an entitled bridge that needs hosting, fetch **cloudflared** at the pinned version for the bridge platform into the bridge's versioned install directory. Include its version and SHA-256 in the bridge release's signed checksum manifest. Use the pinned signature verification in `bridge/src/update/release.rs` and the publishing path in `.github/workflows/release.yml`. Verify signature, platform and digest before atomic install or execution. Build owns pin updates. Permit an operator-selected absolute path via `BRIDGE_CLOUDFLARED_EXECUTABLE`. Verify it against the same signed pin before staging it into the private bridge-version directory. Free and personal-only bridges skip the download. Run as the bridge user with `--no-autoupdate`, a minimal environment and sanitized health categories.

The **bridge writes the ingress file**: exact assigned hostname → `unix:<private-runtime-dir>/bridge.sock`, then `http_status:404`. Keep socket and 0600 credential/config files in an owner-only 0700 directory. Refuse symlinks and unsafe ownership. Adapt `bridge/src/http/{listener,supervisor,runtime,endpoint_state}.rs` to pass Unix streams into the same HTTP router and WSS upgrade handler, preserving deadlines, write-progress accounting, discovery rate limits, Host and Origin checks. Use a bounded local-connector peer bucket. For Unix ingress, represent the local socket/assignment identity explicitly in `EndpointPolicy`; decode older TCP records with their original certificate fingerprint. Preserve the local TLS leaf fingerprint for manual and loopback TLS listeners. Clients check the **paired device identity fingerprint** and the public TLS chain.

Slice 6 must prove the pinned binary honors **local** ingress with `--token-file` and that REST, SSE and WSS traverse the Unix socket. Cloudflare documents that flag for remotely managed tunnels starting in 2025.4.0, and documents a JSON `credentials-file` for local tunnels. If the proposed combination is unsupported, use the local credentials file (account tag, tunnel UUID and connector secret) and **verified loopback TLS** to the existing native listener. Write an exact-host local rule, trust the bridge-local origin CA, verify SNI and preserve Host. Changing the origin socket alone cannot fix credential-mode incompatibility. Supply the secret only through the owner-only runtime file. Both paths keep ingress local and accept no server-supplied destination. [Run parameters](https://developers.cloudflare.com/tunnel/reference/run-parameters/) · [Local ingress and credentials file](https://developers.cloudflare.com/tunnel/features/locally-managed-tunnels/configuration-file/)

The Linux implementation selects the loopback TLS fallback. The pinned 2026.11.2 binary loaded the local Unix rules with a synthetic token file and forwarded REST and SSE, but its HTTP/2 WebSocket path lacked an origin URL host. With a JSON credential file and a bridge-local TLS CA, the same binary forwarded REST, incremental SSE and bidirectional WebSocket data, preserved the exact Host and verified origin SNI. The loopback mock edge uses no Cloudflare account.

The official binary can apply an edge configuration push even when the connector starts with the local credential file and bridge-written rules. The supervisor consumes the pinned binary's structured configuration-applied message privately, kills and reaps the child, withdraws the endpoint, and quarantines that assignment generation across daemon restarts. The mock-edge exercise pushes replacement ingress, waits for the supervised edge transport to close, and checks the replacement origin receives no connection. A request can race between the connector applying a push and the bridge observing the message and killing the child. That window is subject to process and pipe scheduling. Confining the child's outbound destinations is a follow-up.

**Operator recovery.** A quarantined assignment can recover only through an issuer generation rotation. Use the rotation procedure above to withdraw the old origin, delete its DNS and tunnel, and provision a new generation. Daemon restart retains the quarantine for the rejected generation.

**Connector pin updates.** Re-run the ignored `hosted_connector_real_binary_reaps_after_mock_edge_push` test on Linux for each cloudflared pin change. Verify the new release binary against its published SHA-256. Build the library tests with `cargo test --locked --lib --no-run`, set `HOSTED_CLOUDFLARED_FIXTURE` to the verified executable, and run the test binary with `--ignored hosted_connector_real_binary_reaps_after_mock_edge_push --nocapture` in a loopback-only network namespace. The fixture requires Python h2 and OpenSSL. Check REST, SSE, WSS, the exact-host rule and the monitor's response to the edge push with synthetic credentials.

Supervise one child per assignment on the bridge liveness runtime. Start after endpoint acknowledgement, restart with bounded backoff, reap on revoke/rotation/shutdown, and clean stale files and children after crashes. Keep signed API heartbeat and agent work independent. A hosted bridge can appear online while its connector is down. Clients use the device transport projection for endpoint availability. There is no management lease. Issuer grant freshness and provider tunnel deletion enforce revocation even when the bridge misses a change. Qualify on Linux. Add macOS bridge support only with real macOS install, socket, restart and cleanup evidence in slice 6. Otherwise advertise Linux-only hosted bridges for the first release; client support is independent.

## Client selection and security

The authenticated `GET /api/devices` adds a `transport` projection with source (personal, hosted or WebRTC), permitted RTC, setup/update reason, canonical origin when usable and assignment revision. Preserve the existing response fields. `spa/src/devices.js` commits the owned list to `DEVICES_ADDRESS` with its existing account-epoch/generation guards. `spa/src/connection.js` and `core/httpConnections.js` use this cache and account-scoped URL settings for the next attempt. Unknown policy on a new issuer prompts a refresh. Legacy free/manual records and older issuers retain their existing behavior. A network error cannot select another transport. Retire stale origins, handles and in-flight writes on account, device or epoch change. Keep cached work visible.

Each projected `transport` object includes these fields.

| Field | JSON type and meaning |
| --- | --- |
| `source` | `"personal"`, `"hosted"` or `"webrtc"`. Slice 2 reports `"personal"` for a current enabled personal registration and `"webrtc"` otherwise. |
| `rtc_allowed` | Boolean from the issuer. Slice 2 always returns `true`. |
| `reason` | String code for a setup or update reason, or `null` when none is reported. Slice 2 returns `null`. |
| `origin` | String containing the canonical HTTPS origin when a usable registration is known, or `null`. |
| `assignment_revision` | Integer generation of the hosted assignment, or `null` when no hosted assignment exists. |

The response also includes optional top-level `transport_policy: { tunnel_access, promotion_revision }`. These values come from the account policy and are committed with the device list. Missing metadata means no entitlement notice. The active account and promotion revision identify the acknowledgement. An assignment revision identifies an endpoint and can change during the same promotion. The selector uses the per-device projection, including `rtc_allowed`, for dial decisions.

On a fresh authenticated response from a policy-aware issuer, write the projection before dialing. A missing field in a stale cached row is never affirmative RTC permission. Use the same selector in Electron's hosted SPA. Native HTTPS and WSS remain in `desktop/src/bridge-http{,-settings,-network,-ipc,-terminal}.mjs`. For an entitled HTTPS selection, `spa/src/core/httpSession.js` must suppress both RTC terminal fallbacks (missing descriptor and missing `openTerminal`). Gate the signed claim capability independently of the existing app wire version. Use the actual Opening descriptor and native support for terminal dispatch. After inspecting those, **commit terminal compatibility to the account/device/endpoint cache before any view reads it**. Render unknown, WSS or update required from the cache, including a cold mount. Legacy clients can still use compatible verified HTTPS via Add by URL; unsupported bridges/preloads get upgrade guidance. Entitled HTTPS setup never quietly falls back because WSS failed.

Cloudflare terminates public TLS and can read or alter ordinary requests, responses, SSE events, terminal bytes, bearer headers and upgrade tickets. The issuer verifies the signed-in browser or desktop OAuth parent, owner, one-use discovery challenge, paired-device proof, origin and epochs before minting a scoped `bhttp_` bearer. The bridge sends a signed, token-bound introspection assertion to the issuer. A verified bearer opens `/v1/sessions`; protected REST and SSE bind the bearer to the Opening. Terminal WSS requires an authorized Opening plus a one-use, exact-Origin ticket valid at most 15 seconds. Introspection refuses withdrawn hosted authority immediately; existing positive evidence ends within 30 seconds or sooner at expiry. Bearers live at most five minutes, capped by desktop parent expiry.

A hostname alone permits DNS, TLS, preflight, probing and bounded signed discovery. It confers no owner grant, task read/write or terminal access. A stolen connector credential can attach a replica and receive traffic. Keep edge caching and credential/body logging disabled, exact HTTPS/WSS CSP and redirect refusal on both clients. A same-UID process on the bridge is within the local trust boundary. See the [security checklist](<Account Types and Hosted Tunnels Security Checklist.md>).

## Capacity and operator inputs

Cloudflare includes **1,000 tunnels per account** and lists **US$4.50 per additional tunnel per month**. Idle tunnels count. `HOSTED_TUNNEL_CAPACITY` limits each environment's tunnel namespace. `HOSTED_TUNNEL_ACCOUNT_LIMIT` is a required spend ceiling checked against all non-deleted account tunnels, including other consumers. Either limit blocks new creates and leaves existing tunnels running. The checks use a complete inventory snapshot, so the operator must keep headroom for concurrent creates by independent consumers. Cloudflare identifies per-device and per-customer SaaS as supported product uses. [Tunnels for Platforms](https://developers.cloudflare.com/tunnel/features/tunnels-for-platforms/)

**Commercial release gate.** Coverage for Build's exact paid upgrade, file transfers and interactive terminals is unconfirmed. Self-serve §2.2.1 restricts resale and VPN/proxy offerings. Zero Trust §2.2 restricts resale and the CDN terms address large files. Before offering tunnels beyond Zech's own use, obtain written confirmation for Build's account and workload. This business decision sits outside the security score. [Self-serve agreement](https://www.cloudflare.com/terms/) · [Zero Trust terms](https://www.cloudflare.com/service-specific-terms-zero-trust-services/) · [CDN terms](https://www.cloudflare.com/service-specific-terms-application-services/)

**Separate registrable domain.** The same-site decision is closed. Host only bridge tunnels on `builduser.net`. The app, issuer and relay use `getbuild.ing`, and all authentication origins and cookies belong there. Add `builduser.net` to the Public Suffix List before granting tunnels to anyone beyond Zech.
