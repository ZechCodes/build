# Bridge dual-transport acceptance matrix

Preimplementation review for #902 / #907. Base: `12b8f869bd94e259666df69f1a8c0cde5c695982` (fetched `origin/dev`, 2026-10-29). This is a test contract, not approval of a design or implementation. Test names below are proposed unless explicitly identified as existing. Bind exact status codes, limits, scopes, protocol versions and recovery behavior to the approved #903–#906 contract and its fixtures; do not infer them from this matrix.

## Observed seams and risks

- `bridge/src/carrier.rs` `SessionRegistry::admit` currently decrypts before recording a carrier ride. A clear frame cannot safely establish its own session or authorize a channel merely by naming a session. The peer/DTLS fingerprint, authenticated signaling, opening generation and channel must be bound before dispatch. `rtc.clientLanCache`'s client hint is explicitly not an authenticated identity (ARCHITECTURE.md, Paired LAN hint).
- `transport.rs` seals a session key to the API-pinned device key and proves possession in `session_accept`; `rtc.*` remains encrypted on the relay. An attacker can create a sealed init to a public device key, so decryption alone must not be treated as proof of account authorization. Relay token ownership, offer integrity, fingerprint binding and device identity need end-to-end tests, not isolated cryptography tests.
- `FrameIntake` rejects non-signaling relay requests before dispatch. `bridge/tests/relay_end_to_end.rs::an_app_verb_over_the_relay_is_refused_and_reaches_no_handler` and `bridge/tests/rtc_peer.rs::one_session_answers_over_both_channels_and_the_relay_refuses_app_traffic` are existing integration hooks. Carrier tests cover same-key reattachment, different-key refusal, unknown sessions, stale openings and scoped pushes. `spa/test/carrier.test.js` covers chunk reassembly and backpressure. Update these rather than silently discarding their invariants.
- `ChangeBus` is coalesced transient invalidation, not a durable replay stream. #887 proposes a distinct scoped durable sync journal, consistent snapshots, cursor/retention rules and atomic client application; its work must not be assumed present or recreated by SSE. The existing #739 mutation journal is a separate write foundation: admission, identity conflict and crash-recovery tests exist in `bridge/tests/mutation_journal.rs`, but ARCHITECTURE.md says no verb executor is enabled by that foundation slice. Do not claim universal deduplication or no-gap replay from it.
- Existing concurrency hooks include carrier SQL and timing tests, update admission tests and `bridge/src/update/tests.rs::admitted_work_delays_final_idle_handoff_until_its_lease_finishes`. Tests need real adapter entry points and shared handler/admission state; mocks alone cannot prove coexistence.

## Required acceptance tests

| Proposed test | Setup and observable assertion |
| --- | --- |
| `pinned_device_and_offer_fingerprint_cannot_be_substituted` | Pair device A; relay replaces its key, answer, SDP fingerprint or ICE/offer in transit with B's. Each substitution fails authentication or DTLS binding before hello, dispatch or push; unmodified A succeeds. Verify both endpoints and retained encrypted signaling. |
| `unauthorized_or_revoked_client_cannot_mint_or_attach` | Other account, expired/revoked gateway or device credential, and client with only public device key attempt mint, offer and channel attachment. No handler invocation or session ride; authorized same-owner control succeeds. Test revocation while active per approved policy. |
| `relay_rejects_clear_and_encrypted_application_frames` | Inject a valid application request on relay in both formats and malformed/non-signaling variants; no side effects or app push. Existing encrypted request gets documented `unavailable`/`relay_is_not_a_data_plane`; clear/malformed rejection follows approved wire contract. Authenticated `rtc.*` still negotiates. |
| `channel_is_bound_to_authenticated_opening_and_peer` | Establish sessions A and B and both app/term channels; inject A's session id on B's channel, a non-negotiated channel, and traffic before binding. All fail before dispatch; valid A/B traffic routes only to its owner. Cover negotiated channel ids and independent terminal session. |
| `stale_channel_and_callbacks_cannot_cross_reopen` | Close/reopen same session id, then deliver old frames, close callbacks, delayed replies and pushes; none affect or end the new opening. Valid same-opening authenticated reattachment and ICE restart work; cross-opening reattachment fails. |
| `clear_frames_traverse_dtls_and_preserve_framing` | Real local WebRTC peers exchange plaintext application JSON, binary/chunked terminal payloads and pushes over both DataChannels. Inspect the channel boundary for clear application frames, prove encrypted signaling still used, validate ordering, chunk limits, malformed/incomplete chunks and close/backpressure. No inference that application plaintext is plaintext on the network: DTLS remains required. |
| `wire_negotiation_fails_closed_across_versions` | Old/new client and bridge combinations exercise explicit capability/version negotiation, unsupported peers and downgrade/tampered negotiation. No silent clear frame on relay or accidental interpretation of an envelope as a clear frame; fixture compatibility reflects approved transition. |
| `http_disabled_has_no_listener_or_discovery` | Default and explicitly disabled startup bind no HTTP socket, advertise no usable URL and leave WebRTC functioning; enabling, disabling and restart cleanly bind/release only configured endpoint. Invalid or conflicting config fails visibly without weakening WebRTC. |
| `http_identity_scope_and_discovery_are_bound` | Same-owner authorized device succeeds; another account/device, wrong audience, expired/revoked credential and scope escalation fail before side effects. Substitute discovery URL, TLS identity, challenge or redirect target and prove credentials are not forwarded and endpoint binding fails. Test hosted-browser CORS, private-network and certificate failures explicitly against the approved contract. |
| `rest_validation_errors_limits_and_scopes` | For every exposed operation, compare success semantics to WebRTC and assert documented status/error body for malformed JSON, unknown method, invalid arguments, missing/invalid auth, forbidden scope, unavailable, overload and internal error. Exercise exact configured body, pagination, concurrency and timeout boundaries (at limit and one over); no secret leakage or partial mutation on rejection. Validate OpenAPI and wire fixtures. |
| `sse_scopes_expiry_backpressure_and_disconnect` | Subscribe to permitted and forbidden scopes, expire/revoke auth during an open stream, disconnect a slow consumer and saturate its bounded queue. No cross-scope data after authorization ends, no unbounded buffering, prompt resource cleanup; assert documented closure/overflow and reconnect signaling. Include terminal/ephemeral streams separately from durable changes. |
| `sse_recovery_snapshot_and_cursor_contract` | Disconnect around an event, reconnect from cursor, restart bridge, advance retention floor and replace store incarnation. Only assert no-gap replay and atomic cursor/snapshot behavior when #887 capability is implemented and negotiated; otherwise assert explicit invalidation/resnapshot or documented best-effort semantics, never fabricated durable event IDs. Cover stale/foreign cursor and overlapping snapshot/live race. |
| `http_and_webrtc_share_admission_under_load` | Run simultaneous real HTTP and WebRTC reads/writes and SSE/terminal traffic with barriers. Verify each principal gets correct results, limits/fairness are respected, liveness and signaling remain responsive, queues remain bounded and no transport starves or serializes behind a long I/O operation. Record baseline and limits with reproducible measured workload; do not invent a threshold. |
| `disconnect_cancellation_fences_queued_and_running_work` | Disconnect HTTP and WebRTC callers while queued, preparing and running; queued work is removed, owned resources cleaned, old replies/pushes fenced, and a replacement remains usable. Check that cancellation does not falsely claim rollback of a committed or uncertain external operation; test explicit cancellation versus transport loss against the approved contract. |
| `update_drain_covers_both_transports` | Hold HTTP and WebRTC admitted work across update handoff. New writers on either surface are refused during drain, existing leases finish or report the documented uncertainty, then handoff proceeds. SSE shutdown/reconnect does not keep drain indefinitely; rejected writes have zero effects. |
| `same_operation_across_transports_has_one_effect` | Where a specific verb advertises durable operation semantics, submit same principal/operation id and normalized intent concurrently over both transports, lose response and retry across restart: one admission/effect and same recorded outcome. Changed intent or principal scope is rejected or isolated as specified. Also verify uncertain external work is not retried as success; for verbs without that guarantee, assert/document their actual retry semantics rather than promise exactly once. |

Implementation reviews must add executable tests at the owning layers, exercise negative cases before implementation (TDD), run targeted suites and relevant lint/contract gates under `nice -n 10` with exit codes, and run the mandated semgrep before ready. Record exact base/head and which cases were actually run. Coordinate the SSE recovery contract with #887; do not gate this preparation on unimplemented journal guarantees.
