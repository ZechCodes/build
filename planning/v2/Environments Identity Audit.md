# Environments identity audit — M0.2 (#1040)

This inventory classifies **uses**, not variable names. `project_path` remains
the storage field/SQL column name for an opaque project key. `repo_path` remains
a compatibility location projection equal to `home_path`; its presence is not
permission to use that directory as project identity. Identity resolution compares keys for
exact equality, without canonicalizing, splitting or parsing them. `AppState::project_by_key`
is the live key resolver. Legacy creation dedupe remains directory-based.
Scratch identity hashes the complete key bytes. `Path::file_name` supplies only
the historical cosmetic label, preserving migrated folder names; it never
probes the filesystem or resolves a project.

The durable fields `tracker::Task.project_path`,
`store::PersistedPlan.project_path`, `PersistedRun.project_path`,
`PersistedArchivedWorktree.project_path`, review opening/merge/verdict
`project_path`, delivery intent/notice `project_path`, and
`device_owner_projects.project_path` all mean **identity**. Actual checkout,
worktree, source, stage-object-database and display paths mean **location**.
Declarations and comments do not read a value; their lexical matches are
included separately below to make the audit repeatable.

## Decisions and discrepancies

- No wire field, capability or version is added. The plan’s seed table mentions
  adding `project_key` to `project.list`; the task explicitly reserves that for
  M1.1, so M0.2 keeps `path` as the display home directory.
- Cross-project dependency edges are refused by the existing graph contract and
  ARCHITECTURE. The requested sibling dependency regression therefore pins that
  refusal and reconciles a blocker/dependent pair belonging to one opaque-keyed
  sibling while verifying that the other sibling receives no board notice.
- Files moved since the seed table was written: registry and conversation
  consumers live under `app/projects/`, session summaries under `app/`, and
  verdict storage under `store/reviews/`.
- The walk found identity consumers beyond the seed table: persisted run/plan
  writers, incremental mixed task-scope capture, archive joining/deduplication,
  parked ownership/compaction, the SQL device registry and background review
  synchronization. They require the same key semantics; source overlap and
  new-project RPC work remain outside M0.2.
