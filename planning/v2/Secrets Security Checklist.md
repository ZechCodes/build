# Secrets security checklist

**Status:** verified (21/21 controls, 100/100)

**Scope:** user-created Agent-, Project- and Environment-scoped secret attachments from the
SPA's sealed upload through device-vault storage, atomic message binding,
metadata-only delivery/cache/push, issued-session release, raw runtime CLI
output, audit, revocation and lifecycle cleanup.

The score is the verified fraction of all controls, normalized to 100. A control is verified only by shipped code
and a named test or exact source witness. The task branch runs focused tests for
the affected tiers; the complete repository suite remains the serial merge
gate.

**Trust boundary:** Build protects a value until an authorized raw read. The
runtime CLI deliberately writes exact value bytes to stdout; the receiving
agent and downstream transcript or terminal capture are trusted boundaries.
Revocation stops future bridge releases but cannot erase a prior copy or rotate
the upstream credential. The same OS user/root and a device image containing
both vault key and ciphertext remain machine-security boundaries. Unlink is not
a forensic-erasure guarantee.
