# Terminal WebSockets on the bridge HTTP listener

**Decision for #1119.** A URL-connected device carries application requests over HTTPS, changes over SSE, and interactive terminals over one lazily opened WSS connection per SPA tab and selected device Opening. Qualify browser and desktop with relay rendezvous and WebRTC unavailable. Preserve the existing WebRTC terminal path for mixed versions. Production rollout is outside this plan.

Source references below are relative to Build at `234f44a4caef63f85b2534290686b2788c7d6185`. The prior proposal explicitly deferred terminal parity and required a separately authenticated fallback in the interim (`planning/v2/bridge-http-905/PROPOSAL.md:321-331`, `planning/v2/bridge-http-905/PROPOSAL.md:501-513`, `planning/v2/bridge-http-905/PROPOSAL.md:535`).

## 1. Transport and placement

Use the registered HTTPS authority, port, certificate, and native TLS termination. Mount two lifecycle routes alongside the existing Opening and subscription routes. Fix both paths in the clients. Construct WSS by changing only the scheme of the verified HTTPS origin. This gives terminal input and output an ordered, full-duplex connection with its own backpressure. It also lets the HTTP application remain usable during terminal recovery.

| Proposed operation | Owner and purpose |
| --- | --- |
| `POST /v1/terminal-tickets` | The existing browser or native HTTPS endpoint requests admission for its current Opening. |
| `GET /v1/terminal` with HTTP/1.1 Upgrade | The terminal adapter consumes a ticket and binds the Terminal event stream of that same Opening. One connection multiplexes shells and agent screens by `term_id`. |
| Existing roster resource | Keep both background and pane `term.list` calls on REST for this transport. The seven terminal methods in §3 travel on WSS. |

The current router mounts lifecycle and application SSE routes ahead of resource dispatch. The REST catalogue explicitly exports roster metadata and excludes the seven terminal methods. The generator and coverage test enforce that boundary (`bridge/src/http/runtime.rs:244-262`, `bridge/src/http/routes/README.md:82-91`, `scripts/http-resource-manifest.mjs:59-72`, `bridge/tests/http_resource_manifest.rs:29-52`). Update the reasons and document the WS contract separately. Adding terminal methods to the REST operation IDs would advertise request/response routes that cannot deliver terminal output.

Use Hyper's HTTP/1 upgrade support with the already pinned tokio-tungstenite codec. Use TLS to the paired, verified bridge as the confidentiality boundary for both PTY data and device credentials. The WSS path needs no relay session key or second encryption layer. Reuse library handshake/key helpers and enforce the version, mandatory handshake headers, client masking, singleton fields and protocol selection. Keep compression disabled. The crate pins Axum 0.8.9 without its WS feature, Hyper 1.10.1, tokio-rustls and tokio-tungstenite 0.24. The listener currently wraps TLS in `BoundedIo`, serves HTTP/1 without upgrades, holds a socket permit in the HTTP connection task, and joins those tasks on stop (`bridge/Cargo.toml:36`, `bridge/Cargo.toml:48-52`, `bridge/src/http/listener.rs:334-383`, `bridge/src/http/listener.rs:386-424`). Transfer ownership of that permit, guarded I/O and shutdown registration through the upgrade, including its failure path. The listener must still own and join the upgraded task after the HTTP driver returns.

## 2. Authentication and origin

Use an opaque single-use ticket. The browser WebSocket constructor accepts a URL and subprotocols. Its handshake uses credentials mode include and redirect mode error. An application bearer belongs on the authenticated ticket POST. SSE provides a precedent for a consumable handle, but its stream GET *also* verifies a bearer, read scope and session header. Its subscription ID alone cannot authenticate a browser upgrade (`bridge/src/http/runtime/subscriptions.rs:98-124`, `bridge/src/http/runtime/subscriptions.rs:175-202`, `bridge/src/http/runtime/subscriptions.rs:215-235`, `spa/src/core/httpBrowserEndpoint.js:91-111`). [Browser WebSocket handshake and constructor](https://websockets.spec.whatwg.org/#the-websocket-interface)

1. **Issue.** POST with the device bearer, `X-Build-Session`, exact allowed caller Origin and body `{"opening_generation":"…"}`. Verify terminal authority as defined in **Zech’s decision** below. Resolve the exact mounted Opening and its generation. Capture issuer, account, device, credential family, canonical bridge HTTPS origin, endpoint epoch, authorization epoch, verified scopes, grant evidence and *separately* the initiating document Origin. Derive identity from verified server state. The HTTP identity already contains those binding fields, keeps scopes separately and can capture exact request authority on resume (`bridge/src/http/runtime.rs:45-85`, `bridge/src/http/runtime.rs:451-488`). Bind to an expected predecessor for the terminal stream, including its tombstone.
2. **Return.** Reply 201, no-store, with `{ticket,expires_at,opening_generation}`. Generate 32 random bytes, base64url without padding. Store only a lookup digest and the bound state in memory. Lifetime is the earlier of 15 seconds from issue and the issuing proof deadline. Permit one pending ticket per Opening, eight per family and 128 globally. Supersede the prior pending ticket for that Opening. Clean up on expiry, retirement and shutdown. Cap issue rate per family (burst eight, replenish one per second). Refuse overload before allocation.
3. **Redeem.** Offer exactly `build.term.v1` and `ticket.<token>` as subprotocol tokens on the fixed upgrade path. Select and echo only `build.term.v1`. Keep the token out of URLs, logs, trace headers, protocol echoes, close reasons, storage and crash reports. Accept only the canonical host/port and an explicit, single, non-null allowed HTTPS Origin equal to the ticket's caller Origin. Apply that strict Origin check on both routes. Desktop main supplies the trusted hosted app Origin on both. The common HTTP guard currently checks Host and rejects a disallowed Origin *when present* (`bridge/src/http/policy.rs:72-129`). Neither cookies, forwarded headers, the WS key nor a claimed origin confer authority. Browser cookies may accompany a handshake. Ignore them for authority. Before the browser requests a ticket, require a bridge hostname outside the hosted authentication cookie's scope; host-only cookies still span ports. Test a sibling host and a same-host/different-port refusal. The hosted config test asserts a cookie without a Domain attribute (`skriftapp/buildapp/test_dev_deploy.py:466-472`).
4. **Commit admission once.** Validate syntax, live grant, Opening/generation, endpoint configuration, origin, predecessor and capacity before publishing a binding or sending 101. Atomically spend the ticket and compare-and-replace the predecessor. Two redeemers yield at most one socket. If the network fails after consumption, discard it and mint again. Failed or racing upgrades must release reservations and leave unrelated bindings live. Reject queries, redirects, unrecognized subprotocols, absent tickets and arbitrary destination overrides. Use generic authentication/forbidden refusals, 429 for capacity, and no PTY work before successful binding.

**Browser reachability.** Emit an exact WSS host/port alongside the approved HTTPS entries in the account document's `connect-src`. Keep the same bounded owner/client-scoped discovery candidate for the document that completes first use, so the first verified connection works without a second reload. This document allows a network attempt. Discovery and ticket verification still both precede sending terminal traffic. The current policy selects up to 16 enabled, approved, owned, current-epoch endpoints plus one live initiating challenge, canonicalizes them, and emits one private, no-store CSP (`skriftapp/buildapp/bridge_http_policy.py:25-45`, `skriftapp/buildapp/bridge_http_policy.py:48-101`, `skriftapp/buildapp/bridge_http_policy.py:123-158`, `spa/src/core/httpDiscovery.js:77-93`). Preserve ports, nonce, other directives and the existing relay source. Test first-use, stale and cross-account documents in a browser. No wildcard scheme, mixed content, proxy certificate exception or new public listener.

## 3. Binary framing, execution and flow control

**Wire v1.** Send one complete existing application envelope as UTF-8 JSON in one **binary** WS message. PTY bytes stay binary-safe in the existing base64 `data` and `snapshot` fields. This choice costs base64 overhead but lets the bridge send the already encoded, epoch-stamped bytes and lets the SPA use its existing snapshot and cursor code. No second terminal codec is needed. The execution encoder exposes both the payload and its bytes. Screen output, resets and attach replies already encode these fields (`bridge/src/execution/session.rs:255-294`, `bridge/src/screen.rs:161-165`, `bridge/src/screen.rs:307-331`, `bridge/src/app/runtime/terminals.rs:384-394`).

| Direction | WSS v1 contract |
| --- | --- |
| Client → bridge | `{id,method,params}`. Use a bounded unique string ID per outstanding request. Allow only `term.create`, `term.attach`, `term.input`, `term.resize`, `term.ack`, `term.close`, `agent.attach`, plus the existing `ping` for terminal liveness. The sole client lifecycle message outside RPC is the attachment release in §4. Do not accept caller-supplied identity, delivery targets, priorities or durable-write metadata. |
| Bridge → client | Existing correlated success/refusal envelope with the same ID and bridge epoch. Only `term.output`, `term.reset`, `term.closed` may be emitted as unsolicited application messages. Preserve all terminal result fields and close reasons. Match the HTTP greeting epoch before correlation or delivery. WebSocket ping/pong/close are transport controls. |

Admit in arrival order. Validate the allowlist before `Invocation::decode`. Submit to the shared `ExecutionService` with an exact `StreamClass::Terminal` binding and independently fenced reply sink. Track each call through settlement, allowing different terminal lanes to progress concurrently. The shared API has independent Application/Terminal bindings, exact predecessor replacement, a 32-call Opening budget, and pre-encoded sinks. The dispatcher serializes named terminal operations per session/terminal. The default stream-specific request constructor takes lifecycle authority, so expose a narrow variant for a captured terminal proof and binding. Fence queued **effects** as well as replies after socket replacement (`docs/shared-execution-api.md:76-103`, `bridge/src/execution/session.rs:591-685`, `bridge/src/execution/service.rs:18-43`, `bridge/src/execution/service.rs:92-140`, `bridge/src/execution/dispatch.rs:663-704`, `bridge/src/execution/dispatch.rs:1018-1028`, `bridge/src/execution/invocation.rs:29-46`). Preserve shared source checks, shell caps and agent semantics. Keep a WSS-owner attachment map for input, resize and ACK and record server-issued agent rekeys. Cap at 64 current or pending attachment interests per socket, replacing an existing registration for the same terminal atomically. Explicit close of a rostered shell still goes through the shared scoped close handler. Current attach checks scope, input/resize address a tab by ID, and close rejects agent terminals (`bridge/src/app/runtime/terminals.rs:234-247`, `bridge/src/app/runtime/terminals.rs:257-273`, `bridge/src/app/runtime/terminals.rs:289-313`, `bridge/src/app/runtime/terminals.rs:326-349`, `bridge/src/app/runtime/terminals.rs:465-475`).

**Backpressure.** The output sequence is a monotonic PTY **byte cursor per terminal**. The screen flushes on a 10 ms cadence, collapses bursts above 128 KiB to rate-limited snapshots (100 ms), and pauses an ACK-reporting client beyond 1 MiB unacknowledged. Draining to the last sent cursor resumes it with a reset. Legacy clients are exempt until their first ACK. The SPA coalesces applied-cursor ACKs over 250 ms and accepts equal-cursor resets (`bridge/src/screen.rs:66-125`, `bridge/src/screen.rs:194-209`, `bridge/src/screen.rs:222-265`, `bridge/src/screen.rs:296-341`, `spa/src/terminal/session.js:42-51`, `spa/src/terminal/session.js:662-699`). For WSS, enable credit from the attach snapshot, ACK its application immediately, then coalesce as today. Advance WSS credit after the emulator consumes the bytes. Bound pending renderer writes until its completion callback fires. Validate ACK against the highest actually sent for this attachment. Capacity and stall bounds must work even if no ACK arrives.

Pin the following v1 limits in fixtures and measure them in flood tests.

- Cap an inbound message and aggregate fragments at 128 KiB, decoded input at 64 KiB, and outstanding WSS calls at eight within the shared 32. Split long pastes into ordered byte chunks. Validate dimensions before allocating a PTY/grid (1–512 columns, 1–256 rows, at most 65,536 cells). Refuse an oversized snapshot explicitly. Never truncate a UTF-8 payload or a screen. Reject text, malformed JSON, excess nesting, duplicate outstanding IDs, and oversized messages before dispatch.
- Per socket, reserve 1 MiB inbound and 2 MiB outbound with at most 128 queued messages in either direction. Cap each outbound message at 1 MiB. Count a dequeued write through successful flush or drop. Reserve capacity for correlated control replies and `term.closed`; if a complete message cannot be delivered, terminate that binding and recover by snapshot. Bound encoding/fragment/write staging to a further 1 MiB per socket, use a bounded serializer/preflight for large shared payloads and verify codec buffer sizing. These are adapter wire allowances. Separately measure parser, domain-object, TLS and kernel costs during qualification.
- Limit to 16 held WSS allocations across the listener, four per credential family and one current binding per Opening (64 MiB aggregate adapter allowance). A superseded socket counts until its I/O drops. Keep a separate pool from RPC and application SSE, which currently reserve 288 MiB and 32 MiB respectively (`bridge/src/http/limits.rs:10-40`). Reserve before 101. Reaching a transport quota must leave REST and SSE headroom.
- The pump uses nonblocking bounded enqueue. On overflow, retire only the affected socket. Cut a blocked write/flush after 10 seconds. Give a client paused solely for missing ACK progress the same bounded recovery window. An idle quiet shell has no outstanding credit debt. Check authority while parked. Mirror item/byte limits in the browser's pre-attach and orphan queues, `bufferedAmount` send gate, and desktop's outstanding IPC deliveries. On overflow fence the socket and cancel unsent input. The current orphan cap is 64 frames and pre-attach output can queue ahead of the attach response (`spa/src/terminal/session.js:37-40`, `spa/src/terminal/session.js:393-410`, `spa/src/terminal/session.js:641-650`). The listener already uses a 10-second stalled-write deadline (`bridge/src/http/sse.rs:13-17`, `bridge/src/http/listener.rs:88-104`).

## 4. Attach, recovery, expiry and drain

**First attach and reconnect.** Retain the SPA's lazy owner and pane registrations. A pane unmount cancels its ACKs. If siblings remain, send a binary transport control `{"type":"detach","attach_id":"…"}`, using the original attach request ID as the interest handle. Drop only that exact registration on this binding, including a pending agent attach. Ignore duplicate or stale releases. The detach control has no domain dispatch and cannot close a shell or interrupt a sibling. Release the WSS binding when its last consumer leaves. Never kill a PTY on disconnect. Only explicit `term.close` ends a shell. Socket loss rejects outstanding calls, with uncertain delivery for handed-off effects. Retry the *connection* with bounded jittered backoff and a new ticket while interested. Restore with `term.attach` or `agent.attach`. Never replay input, create or close. Refresh roster metadata when a create/close result is uncertain. An agent attach can return a retained screen, a blank screen pending birth, or a no-terminal refusal. Preserve rekey-on-birth, source/workspace guards and pane cancellation (`spa/src/terminal/pane.js:1-4`, `spa/src/terminal/session.js:263-301`, `spa/src/terminal/session.js:305-354`, `spa/src/terminal/session.js:357-390`, `spa/src/terminal/session.js:419-444`, `spa/src/terminal/session.js:591-619`, `spa/src/core/projectTerminalRpc.js:18-30`, `bridge/src/app/runtime/agents/endpoints.rs:72-95`).

**Recovery boundary.** The parser is configured for 2,000 scrollback lines, but its attach snapshot serializes the current formatted screen. Registration and snapshot share the screen lock. The bridge sends the cursor and dimensions in the reply (`bridge/src/screen.rs:131-145`, `bridge/src/screen.rs:161-165`, `bridge/src/screen.rs:429-496`, `bridge/src/app/runtime/terminals.rs:384-394`). Rebuild the visible screen, discard duplicate bytes through that cursor, accept an equal-cursor reset, and live-tail contiguous output. An unexplained gap requires reattach. This matches WebRTC recovery. Historical byte replay or recovery of the client's entire scrollback would be a separate feature.

**Proof lifetime.** On mint/redemption retain exact write-capable proof. On a successful Opening PATCH, refresh the live terminal proof *only* after fresh verification of the same identity, scopes and credential (use a non-exported digest/identity). Publish the replacement evidence under the binding's gate before its old deadline. Hold the original authorization on each already-admitted request. A scoped-down renewal retires the terminal. Credential rotation requires a fresh ticket/socket and snapshot attach. Ordinary REST reads and application SSE renewal cannot extend terminal authority. The existing PATCH revalidates only read scope, compares the HTTP identity and resumes the exact Opening. That identity excludes scopes. Grant evidence caps freshness by token expiry and verifier window, and observed revocation is checked by the lease (`bridge/src/http/runtime/renewal.rs:43-101`, `bridge/src/http/runtime.rs:53-73`, `bridge/src/http/auth/client.rs:82-105`, `bridge/src/http/auth/grant.rs:93-128`). Browser and native already arm hard timers and renew the Opening (`spa/src/core/httpBrowserEndpoint.js:71-89`, `desktop/src/bridge-http.mjs:250-274`, `desktop/src/bridge-http.mjs:297-335`).

At expiry, observed revocation/logout, Opening retirement, endpoint rebind, epoch change, or owner replacement, invalidate ticket and socket authority. Fence intake, queued handlers, producer callbacks, response delivery and the actual TLS write/flush; wake a parked reader/writer without waiting for inbound traffic. Drop pending bytes and never flush sensitive output to announce a close after authority ends. Already delivered bytes or an admitted PTY write cannot be recalled. Cleanup must compare exact binding identity under the same gate as replacement. A late close, ACK or detach using just the session ID could otherwise touch a successor because screens index attachments by that ID (`bridge/src/screen.rs:194-209`, `bridge/src/screen.rs:222-231`, `bridge/src/screen.rs:268-272`, `bridge/src/screen.rs:515-521`). Retire the socket, its attachments and waiters independently of the application binding.

**Update drain.** Use the existing update admission for each terminal effect. An idle WSS connection holds no permanent update admission lease. Once drain wins, stop mint and redemption, invalidate pending tickets and bindings, wake reads/flushes, cancel queued interest, and join upgraded tasks within the existing five-second socket teardown. Keep settlement guards through admitted work. After restart, require fresh verification, a new Opening and a new binding. The shared handler gates requests across handoff and the listener already stops acceptance and joins or aborts connections. Extend the cross-transport drain witness with active, pending-upgrade and stalled WSS peers (`bridge/src/app/rpc.rs:138-165`, `bridge/src/app/rpc.rs:223-230`, `bridge/src/update/admission.rs:53-71`, `bridge/src/update/admission.rs:86-120`, `bridge/src/http/listener.rs:370-383`, `bridge/src/http/runtime/tests/subscriptions/cross_transport/drain.rs:6-10`, `bridge/src/http/runtime/tests/subscriptions/cross_transport/drain.rs:40-83`).

## 5. Capability, version and client selection

Add an optional `terminal_websocket: {"version":1,"protocol":"build.term.v1"}` to `Opening.transport` on POST and PATCH. Keep the legacy `terminal:"webrtc"` member as the fallback declaration. Only advertise the extension when the two WSS routes and their security/lifecycle handling are available. Describe transport availability independently of grant permission: the ticket endpoint makes the authority decision, and a scope refusal must never select another transport. Use the next available additive wire minor (3.42.0 on this base) and named greeting capability `term.websocket` for implementation support. Require both the Opening descriptor and capability for WSS. Retain v1 of the resource manifest, the current SPA minimum and the existing session POST shape.

The Opening emits the literal legacy field. Its request denies unknown fields. Both the old SPA and old native main insist on the legacy value, but ignore additional transport members. The SPA also hardcodes its chosen terminal transport. The base wire is 3.41.0, the SPA accepts 3.24 through the end of major 3, and the documented wire gate pins the previous-minor manifest, hello fixture and capability metadata (`bridge/src/http/runtime.rs:669-672`, `bridge/src/http/runtime.rs:828-850`, `spa/src/core/httpSession.js:9-17`, `spa/src/core/httpSession.js:147-150`, `desktop/src/bridge-http-contract.mjs:200-212`, `bridge/src/api/mod.rs:83`, `bridge/src/api/mod.rs:111`, `fixtures/api/versions.json:2`, `spa/src/core/bridgeApi/index.js:26`, `ARCHITECTURE.md:5995`).

| Combination | Terminal selection |
| --- | --- |
| New browser/SPA, new bridge | Choose WSS at first terminal demand. Create zero RTC owners, peer connections, gateway tokens, relay sockets or ICE requests for this URL device. |
| Old SPA or old native main, new bridge | Legacy SPA reads the old field. New SPA feature-detects the **complete** native terminal IPC before selecting WSS. With an older main it uses the existing independently authenticated RTC owner. |
| New SPA, old bridge, or a future unsupported WS version | Use declared WebRTC fallback for terminals only. The application keeps its compatible HTTP Opening. A malformed or contradictory claimed v1 descriptor is a terminal protocol error. |
| WSS selected but ticket refused, TLS/CSP/upgrade failed, socket full or stalled | Report the actual terminal failure. Retry transient faults on WSS with a fresh ticket. An authorization failure requires current authorized credentials. Keep the terminal on the selected WSS path throughout recovery. |
| WebRTC-selected device | Use its existing terminal session mint and DataChannel, independent of WSS availability. |

**SPA ownership.** Today the URL path creates a lazy RTC helper tied to the HTTP session, and the terminal manager independently consults the peer-link owner during device follow. The terminal session constructs an encrypted RPC adapter, and the existing corner label follows the saved HTTP preference (`spa/src/core/terminalPeerLinks.js:13-32`, `spa/src/core/terminalPeerLinks.js:82-94`, `spa/src/connection.js:99-107`, `spa/src/connection.js:612-633`, `spa/src/terminal/manager.js:117-132`, `spa/src/terminal/manager.js:156-171`, `spa/src/terminal/session.js:514-533`, `spa/src/core/surfaceTabs.js:84-108`). Select the owner *before* those lookups. Give the shared terminal manager a small call/push/close interface, keeping RTC encryption in its RTC adapter. The WSS adapter uses the Opening epoch and socket generation, never a fabricated RTC key. Bind attempts, frames, timers and diagnostics to tab/device/account/Opening. On device switch dispose the old owner before input can target the new one. Keep terminal failure local. Render the WebRTC badge only for negotiated legacy fallback on an HTTP device; store the selected mode with the device's presentation metadata, so disconnects preserve the cached surface (`ARCHITECTURE.md:4683-4688`).

**Desktop ownership.** URL discovery selects native IPC when present. Main validates the sender, exact top-level frame and hosted app URL, retires owners on navigation/crash, and validates Opening generation and expiry. The current preload exposes finite operations; SSE has sequenced, acknowledged IPC delivery (`spa/src/core/httpConnections.js:56-66`, `desktop/src/bridge-http-ipc.mjs:7-25`, `desktop/src/bridge-http-ipc.mjs:75-117`, `desktop/src/preload.cjs:3-18`, `desktop/src/bridge-http.mjs:250-274`, `spa/src/core/httpDesktopEndpoint.js:31-82`). Add typed terminal open/call/consume/close and terminal events on opaque, owner-bound handles. Main obtains the ticket and makes the WSS connection with exact Origin, platform TLS validation, redirects and compression disabled. Package a reviewed WS client with explicit payload limits as a direct runtime dependency if the native client cannot enforce these controls. Never hand the renderer a ticket, bearer, URL override, arbitrary header or network primitive. Bound and acknowledge IPC deliveries independently of terminal cursor ACKs. Fence buffered IPC and in-flight replies on renderer navigation, logout, credential change, stale frame and native handle close.

## Zech’s decision — does existing URL approval include a shell?

**Recommendation. Include shells in existing URL approval.** Require a currently verified owner credential with both `bridge:read` and `bridge:write` to mint or renew terminal authority. Apply it to existing approved URL families as well as new ones. Refuse read-only tickets even for agent viewing: snapshots can contain sensitive output and an attach can resize a live PTY (`bridge/src/screen.rs:747-769`). A fresh ticket is still required per socket.

**What that credential can do today.** Hosted issuance names the read and write scopes. Mounted resource requests require read and check write for mutations. The catalogue includes agent start, scoped file writes and thread messages. The mounted HTTP test asserts an agent-start result; the handler enqueues a turn for the addressed agent and drains it. A Codex harness runs a local process, opens a thread with full-access sandbox settings and reports command-execution results. This establishes a path from an owner-issued HTTP write grant to **agent-mediated local command execution** on a suitably configured machine. It does not guarantee that a particular prompt executes or that a runnable harness exists (`skriftapp/buildapp/bridge_http_auth.py:38`, `bridge/src/http/runtime.rs:313-322`, `bridge/src/http/runtime.rs:390-405`, `bridge/src/http/runtime.rs:1663-1694`, `bridge/src/http/routes/resources.tsv:7`, `bridge/src/http/routes/resources.tsv:43`, `bridge/src/http/routes/resources.tsv:143`, `bridge/src/app/runtime/agents/endpoints.rs:218-251`, `bridge/src/app/conversations/post.rs:748-813`, `bridge/src/harness/codex_app_server/process.rs:111-130`, `bridge/src/harness/codex_app_server/protocol.rs:100-127`, `bridge/src/harness/codex_app_server/translator.rs:710`).

WSS makes that reach **direct and interactive** and usable without an agent. The user shell runs with the user's shell environment. Agent harnesses and user terminals differ in inherited daemon identity. The current catalogue excludes terminal control and the existing HTTP path gives only roster metadata (`bridge/src/terminal_environment.rs:1-15`, `ARCHITECTURE.md:103-109`, `bridge/src/http/routes/README.md:82-91`). The product decision is whether the original owner approval covers that difference. Parity favors one device approval. Fresh online proof, explicit write scope and a revocable terminal binding put a check at each use.

**If Zech requires separate consent.** Keep the same routes, wire protocol and slice order below. In **B** extend hosted grant issuance and introspection in `skriftapp/buildapp/bridge_http_auth.py`, the HTTP family model and its migration, the owner consent endpoint, and Rust scope verification with an explicit `bridge:terminal` entitlement in addition to read+write. Migrate existing families to *off*. Preserve plain read/write grants for old bridges, including renewals; only issue the additional scope after capability-aware, owner-confirmed authorization for the exact endpoint/family. Rejecting unknown scopes is existing verifier behavior (`bridge/src/http/auth/client.rs:131-149`). In **F/F2 and G/G2** add consent/decline and reauthorize handling for browser/native. Revoke and rotate on withdrawal, fence open sockets, and keep REST usable. In **I/J** add migration, old-verifier, withdrawal and consent witnesses and document the choice. This is the only open product decision; the protocol and implementation dependencies can be reviewed now.

## 6. Security checklist delta and acceptance

Create `planning/v2/Terminal WebSocket Security Checklist.md` during implementation. **Release requires 100/100 with executed evidence at the candidate SHA.** Each of the ten pending witnesses is worth ten points. The Account HTTP checklist records author evidence and its acceptance boundaries, including the 30-second verification freshness ceiling. The desktop checklist covers renderer isolation, navigation and header authority; the update checklist scopes its existing verification to update controls (`planning/v2/bridge-http-910/Account HTTP Security Checklist.md:3-15`, `planning/v2/bridge-http-910/Account HTTP Security Checklist.md:20-43`, `planning/v2/Desktop Security Checklist.md:20-25`, `planning/v2/Bridge Update Security Checklist.md:3-10`). Link the WSS evidence back from those checklists without transferring their scores.

| Points | Control | Witness required for credit |
| ---: | --- | --- |
| 10 | Verified owner and write authority | On a real verifier/listener, accept the selected consent policy. Reject read-only, wrong account/device/family/issuer, stale endpoint/authorization epochs and wrong generation before a PTY or producer exists. |
| 10 | One-use tickets | Concurrent redemption has one winner. Expiry, reuse, supersession, rotation, DELETE and restart fence stale tickets. Repeated issue is bounded and the registry releases memory. |
| 10 | Origin, TLS and CSWSH protection | Reject missing/null/duplicate/unlisted/other-allowed Origin, incorrect authority, redirect and untrusted certificate. Cookies alone cannot upgrade. Native sets the trusted app Origin. |
| 10 | Terminal-only execution | Exercise every admitted method, agent and source/workspace scope. Reject unrelated methods, caller authority overrides, wrong-class bindings, cross-device ID confusion and stale attachment effects. SSE never receives a terminal byte. |
| 10 | Revocation and expiry | Test fresh write-capable PATCH, read-only renewal, rotation, expiry without traffic, logout, disable/rebind and races with blocked input or pending TLS write/flush. Show no subsequent effect admission or output after the fence. |
| 10 | Bounded cost and fairness | With a flooding PTY, absent/slow ACKs, stalled socket, saturated family and oversize/fragmented messages, verify byte/item peaks, physical socket permits, stall deadline and RPC/SSE progress for another client. |
