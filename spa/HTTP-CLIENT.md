base `12b8f869bd94e259666df69f1a8c0cde5c695982`. Its controlling architecture is

application-binding disposition.

`scripts/http-resource-manifest.mjs` from the explicit bridge route catalogue

`4069a7f03574f870c2de796d1a6486dc24edc01c86974b7460053fee1c6da996`.
The original #915 import came from coordinator-released committed head

The SPA imports this single canonical artifact; it has no independent REST
method catalogue. `httpManifest.test.js` pins its bytes, count, operation IDs,
parameter placement, limits and terminal/signaling/QA exclusions. The sealed-only
`secrets.create` request is capped at 64 KiB; value retrieval has no public HTTP
route. Create bypasses the generic persisted write-intent journal. All four
secrets verbs and `secrets.attachments`, `secrets.sealedUpload` and
`secrets.metadataEvents` remain explicitly withheld from greeting capabilities
until slice F enables the complete feature. `UNADVERTISED_CAPABILITIES` in
`bridge/src/api/mod.rs` names that gate; enabling it requires moving the three
feature names into `FEATURE_CAPABILITIES` and removing their method exclusions.
Future manifest changes require regenerating both HTTP artifacts and reviewing
the exact hash and operation list together.

The authenticated Opening must advertise all required operation IDs, resource
manifest version 1, `terminal: webrtc` and `durable_events: false`. Opening's
greeting establishes initial epoch authority. The application stream hello must
arrive before the actual `session.hello` resource activates binding-owned
producers. Logical subscriptions then settle successfully before ordinary reads
and actions are released. Current-state refresh follows; there is no durable
cursor, event replay or no-gap claim.

Stream loss/reset, authorization loss and uncertain stream creation close the
exact old execution Opening. Recovery opens a fresh one; it never retries an
ambiguous stream replacement or transfers pending actions to another transport.
Every request captures its original subscription handle. Terminal I/O uses the
separate WebRTC owner supplied by #909, with exact HTTP-session closure cleanup.

HTTP waits for final JSON; it does not synthesize admission receipts or call
`onReceipt`. A deadline after send reports uncertain delivery. Default request
deadline is 12 seconds; `workspace.get` and explicit `null`/`0` wait for caller
cancellation or actual completion, independently of authorization hard deadlines.
Durable write behavior remains governed by the existing per-method allowlist.

Only address/device/endpoint-epoch/family hints and explicit transport choice
persist in account-scoped UI storage. Tokens stay in browser memory or desktop
main. Every restored hint requires hosted renewal, including exact endpoint
binding. Relay presence controls WebRTC eligibility; an explicitly selected HTTPS
endpoint remains eligible for authenticated attempts independently of relay
presence. Account device removal and HTTP revocation/expiry still retire it.

The desktop wrapper generates a fresh UUID before installing its event listener
and invokes `subscribe(handle, {kind: "application"}, {requestId})`. Every native
event, including reset/closing controls, must carry the immutable envelope
`{handle, requestId, stream, sequence, event, data}`. Main binds the opaque handle
to its owner/navigation generation and captures the caller's attempt ID; these
fields grant no authority and are not durable cursors. The wrapper discards
missing/foreign handle or attempt correlation before serialization or queue
accounting, then also filters the exact returned stream UUID. Queued controls
from retired attempts on the same handle cannot affect a pending successor.
The SPA allows only one subscription attempt per endpoint, including while the
invoke is pending; recovery closes it and obtains a fresh handle and Opening.
Native retains its independently fenced sequential CAS/rebind API and rejects
concurrent or reused attempt IDs. This contract requires the separately reviewed
#914 correlated-envelope correction; the earlier native head supplies no safe
pre-response correlation and must not be paired with this wrapper.

The real HTTPS witness uses an isolated fixture server and an ephemeral CA,
exercises production browser adapter entry points, and separately verifies
untrusted-certificate refusal. It is not acceptance of the Rust runtime, hosted
CSP/CORS, browser local-network permission or native packaging. Those require
the reviewed integration slices and #913 qualification.
