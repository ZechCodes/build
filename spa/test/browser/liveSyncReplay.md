# Mounted live-sync replay

Run `nice -n 10 node test/browser/profileLiveSync.mjs /tmp/live-sync.json --board204 --current` from `spa`. Omit `--current` for the pinned pre-change baseline, 83d5c9fd. `--cpu` saves an optional CDP CPU profile; timings with that flag include profiler overhead. `--cache-canvas-rect` is a fixed-viewport geometry ablation; `--canvas-off` and `--inbox-off` independently disable those consumers during measured traffic. `--sensitivity` uses 36 rather than 120 frames.

The fixture seeds the sanitized retained scale: 1,673 records, six projects, 104 workspaces, 204 row records, 110 threads, 858 task details, nine roster agents and one policy. Startup sync may populate additional records; reports distinguish `seedRecordsBeforeWarm` from `seedRecords`. The mounted UI has four visible inbox rows, one animated canvas and 1,284 DOM elements. Actual inbox and agent-rail code renders the conversation; static detail padding supplies the remaining DOM size.

Current board membership, task-list membership and read-through were not measured live. They are explicit synthetic parameters: board membership six by default or 204 with `--board204`, 143 tasks per project, two watched tasks and read-through 1100. Retained counts do not establish current membership. A branch route mounts the actual canvas without reconstructing the unknown live route.

Input sends revision-only board hints, row updates, thread deltas and unrelated terminal notifications every 375 ms. Warm startup and the 32-notification no-op probe quiesce before traffic counters reset. Instrumentation records receipt, queue admission, worker start, exact transaction commit and actual rail mutation followed by animation frame. Quantiles use nearest rank, `ceil(n*q)-1`. CPU wrappers account for nested wrappers but are not a complete browser CPU profiler.

The short Vitest replay guards read counts, actual mounted-paint scheduler turns, bounded drain turns, empty queues, exact pushed state/messages, monotonic bounded read markers, entity removal and conversation reset. Count limits avoid load-sensitive timing assertions. Sustained CLI results supply elapsed latency measurements; they cannot establish that the separately observed live 17.4-second p95 was reproduced or eliminated.

`--warm-catchup` starts traffic without quiescing startup: cache cursors begin at 1080 while the synthetic server has 20 additional messages per active thread. All thread-page RPCs wait behind a five-second fixture gate; the producer continues during the hold and after release. The default uses all-empty tips as a repair stress case. `--mixed-warm-tips` uses five carried and three empty primary tips per eight frames, with repeated empty duplicate tips. RPC wait phases, first/second-half body pending peaks, catchup demand and actual mounted progress before producer completion are reported. The deliberate hold contributes to measured end-to-end latency and must be identified separately from product delay.

Mounted priority comes from the actual agent rail by default. `--explicit-thread-priority` preserves an early diagnostic's explicit scope registration and is not used for final mounted acceptance. The cache observer only records cache delivery; the rail mutation observer plus animation frame records visible delivery. `mountedPriorityKnownAt` reports when the real visible identity becomes known. Warm completion requires initial/full passes, body jobs, repair demands, appliers and IDB transactions to drain; `bodyDrainMs` distinguishes the foreground queue from later bulk source work.

`--sustained` runs 360 frames without the independent removal/reset controls. It records whether the first source pass finishes while the producer continues, and whether mounted paint continues afterwards. The default stress stream emits three change items per frame. `--representative-rate` emits two: board plus body, with a terminal update replacing the board hint every twentieth frame. Actual input duration, frame rate and change-item rate are reported separately from drain time. `--body-backlog64 --board204` first queues 64 valid retained entity states; `--no-rpc-hold` separately checks mounted priority without the deliberate repair hold. The backlog oracle checks final canonical fields and distinct commits, including the mounted commit's position among nonmounted commits. `--revision=<sha>` pins any historical source for a matched comparison.

Report raw latency, latency minus only the measured own-repair gate overlap, and raw latency for tips received after that gate ends. Keep failed stress thresholds visible. Neither deliberate fixture holds nor unrelated host load establish a product regression; neither may be silently subtracted without an attributable measurement.

The pure `liveSyncDelivery.mjs` report matches stable-generation covering highwaters for admission, worker start and commit, while requiring each actual mounted sequence. These are observational coverage boundaries rather than per-job causality. If a concurrent source pass commits before the queued body worker starts, that unordered interval is counted separately instead of reported as a negative causal latency.

Live evidence has two separate boundaries. The older capture's 26 matches give nearest-rank p95 17,385 ms. The later reopened retained browser matched only 8 of 25 highwaters, with a 144,434 ms maximum among those matches and 17 highwaters still uncommitted at capture end; that censored capture has no representative p95. Passing isolated fixtures does not prove that the live censored tail is eliminated.

Accepted SLA captures keep the optional CDP CPU profiler off; common stage/read/UI instrumentation remains enabled. A diagnostic CPU-on capture overlapped other host test workers, so its incremental profiler overhead was not isolated. Do not treat its wall-clock difference from a CPU-off run as a causal overhead estimate.
